# EMP E r0.1 — 外部API / Codex接続契約

エントリは `src/emp-e.js`。宣言ファイルは `src/emp-e.d.ts`。プレビューのDOM、CSS、requestAnimationFrame、ループ入力はAPIモジュールへ入っていない。ゲーム側はこのファイルをimportし、必要なタイミングでAPIを呼ぶ。ブラウザnative ES modulesのみ、ランタイム依存0。

## 最小統合

```js
import { EMPEffects } from './emp-e/src/emp-e.js';
const emp = await EMPEffects.create({
  canvas: document.querySelector('#emp-layer'),
  onError: console.error,
});
emp.setView({ center: { x: 640, y: 360 }, pixelsPerGamePixel: 1 });
// 音声の有効化はクリック等のユーザー操作中に行う。
startButton.addEventListener('click', () => emp.enableAudio());

function onChargeStarted(event) {
  emp.charge({ id: `${event.id}:charge`, actorId: event.actorId,
    atMs: event.actorMs, origin: event.emissionPosition, phase: event.phase });
}
function renderFrame(game) {
  // game.actorMsは全イベントで比較可能な、外部ゲームが所有する共通時刻。
  emp.update({ actorMs: game.actorMs, rate: game.speedMultiplier });
  emp.setListener(game.listenerPosition);
  emp.render();
}
```

このモジュール自身はRAFを開始しない。canvasは透明で、外部の背景・UIを描画しない。ホスト所有のGPUDeviceを `create({device})` で渡せる。その場合 `dispose()` はdeviceを破棄しない。共有deviceへの別のrender passを注入する低水準APIではなく、専用canvas/texture群を所有するレンダラーである。

## 座標と時間

`Point = {x,y}` はgame px、+X右・+Y下。`origin` は発生点であり、画面中央ではない。`setView.center` は画面中央に写るゲーム座標。`pixelsPerGamePixel=1` ならH64=64 CSS px。DPRは内部画素密度だけでゲームの射程を変えない。ブラウザズーム100%が実寸確認条件。

幾何内の仮想深度は遮蔽・立体構造のためだけに使い、ゲームの距離・中点・命中判定には使用しない。B設計上の1 H64=1 mは造形の単位換算であり、ゲームpxと実世界メートルの実測対応ではない。

`atMs`、`actorMs`、寿命はすべて同一のactor-time。`rate` はそのactor-timeが実時間に対して進む倍率。アニメーションと音声に同じ値を渡す。rate=0で停止、rate=2で実時間寿命が半分になる。音高もrateに追従する仕様で、音高保持のタイムストレッチではない。途中でrateを変更してよい。負のrate、8より大きいrate、非有限値は拒否する。

時刻を巻き戻す場合は `reset(newActorMs)` 後に必要なイベントを再投入する。巻き戻しはリプレイepochであり、ゲームの実封鎖・cooldownを解除しない。複数アクターに独立した時間倍率があるゲームでは、ペア判定可能な共通時刻への変換をホストが行う。個別時計を無変換で混在させない。

## 効果別API

| API | 必須データ | 所属位置・寿命 |
|---|---|---|
| `charge({id,atMs,origin,actorId?,phase?})` | 開始ID、actor-ms、発動点 | 発動者位置、1200ms |
| `normal({id,atMs,origin,targets,phase?})` | release ID、発動点、`[{id,position}]` | 発動者から対象へ、520msの可視場 |
| `suppression({id,atMs,origin,targetId?,durationMs?})` | 確定命中のID・時刻・対象位置 | 対象位置、既定7000ms |
| `resonance({id,atMs,origin,a,b})` | 確定ペアID、発生時刻、中点、発生点A/B | 中点、1600ms |
| `cancellation({id,atMs,origin,a,b})` | 上と同じ。逆位相と外部で確定 | 中点、1600ms |

通常の可視到達はreleaseから180msという本作の美術選択。ゲームの命中時刻を勝手に遅延する機能ではない。ホストが確定した命中時刻で `suppression` を呼ぶ。プレビューでは可視到達と同時の180msを使用する。

`normal` は `targets:[]` でもよく、その場合発動点の短い開裂だけを描き、架空の対象を作らない。射程外260px超の対象は拒否する。射程境界260pxは受理する。複数対象へ同じreleaseから描画できるが、通常SFXはrelease IDにつき一回だけ。命中対象ごとにrelease音を増殖させない。

ペアAPIの `origin` が `(a+b)/2` と一致しない場合は拒否する。浮動小数点誤差の許容は1e-5 game px。A/Bの距離が520pxを超える場合も拒否する。ペアAPIは**ホストが既に位相・時間窓を確定したイベント**を受け取るため、API自体がphase履歴の探索やペア消費を行うわけではない。

`moveAttachment(id, position)` はcharge/suppressionのみ追従位置を変更する。継続中の対応音声voiceの音源位置も更新し、音を再起動しない。通常放電とペアのsnapshotは不変。発動後にアクターが動いても過去の共鳴中点が勝手に移動しない。targetsの移動中に新しい命中点へ放電を曲げる必要がある場合は、別途ホスト側の仕様調整が必要。

## ペア判定ヘルパー

```js
import { pairResult, classifyResonance } from './emp-e/src/emp-e.js';
const pair = pairResult(
  { id:'release-a', actorId:'actor-a', phase:1, atMs:1200, origin:{x:100,y:200} },
  { id:'release-b', actorId:'actor-b', phase:1, atMs:2100, origin:{x:500,y:200} }
);
if (pair) {
  emp[pair.kind]({ id:'pair-a-b', atMs:pair.atMs,
    origin:pair.origin, a:{x:100,y:200}, b:{x:500,y:200} });
}
```

`pairResult` は純粋関数で、同一イベント・同一発動者は除外する。境界は時間差≤1200ms、距離≤520px。phase一致で共鳴、異なると相殺。時刻は遅い方、中心は発生snapshotの中点。

「EMPが発生する時刻」は本プレビューではcharge完了時のreleaseと解釈した。ホストの契約が別の発生イベントを指す場合、比較する `atMs` の意味をゲーム側で揃える。描画コードがユーザーの未提示ゲーム実装を知っているとは仮定していない。

3つ以上の競合EMPのペア選択、既消費ペア、ネットワーク順序、チーム判定、damage量、無敵、相殺後に通常効果を取り消すかどうかは未提示のゲーム契約なので**この資産は決めない**。pair helperは自動的に通常放電・通常命中を削除しない。

`classifyResonance(center,target)` は `kill` / `body_damage` / `outside` を返す。110px以下はkill、110px超260px以下はbody_damage。それ以上はoutside。これは分類でありHPを変更しない。相殺に新しい殺傷半径を作らない。

## SFX、重複、容量

`id` はグローバルに一意のstring。duplicateは `{accepted:false,reason:'duplicate'}`、容量超過は `reason:'capacity'` で、再発音しない。acceptedの結果は必ず確認する。既定は最大256 retained events、100,000 remembered IDs。終了した幾何はpruneされるがID記録は明示resetまで保持される。上限は安全なscene境界でresetする設計であり、無制限の長期sessionを自動的に回すものではない。

音声は48kHzで手続き合成し、6.5kHzの二段soft low-passを通したPCMをAudioWorkletへ渡してactor-timeで再標本化。rate2で高域が移動するための緩い帯域制御であり、完全なband-limited resamplerではない。通常2200、共鳴2600、相殺1800 game pxでゼロになる滑らかな距離ゲインを使う。初期値に物理メートル単位のPannerNode減衰を流用しない。chargeの距離目安は通常と同じ2200、任意のsuppression音も2200とした美術選択。

`enableAudio()` 前のイベントは再生しない。後で有効化した際に過去の起音をまとめて再発音しない。プレビューの音声ボタンは新しいaudition epochを開始する。最大64音声voice。超過時は最古voiceを落とすため、64同時超の音声完全性を保証しない。`sound:false` で効果ごとに無音化できる。suppressionは既定無音。

`setListener({x,y})` と `setVolume(0..1)` を変更可能。通常/charge音源は発動点、共鳴/相殺音源は中点。実音速に基づく伝播遅延、壁越し音響、ドップラーは追加しない。再生rateに伴う音高変化は仕様。実機でのlatency/jitterと知覚評価は未確認。

## 遮蔽と描画制約

`setOccluders([{x,y,w,h,depth,color}])` は同一WebGPU座標系で矩形の不透明遮蔽面を供給する補助API。プレビューでこの機能を切替できる。一般的なゲーム全体のdepth textureを自動的に取得する機能ではない。ゲームの任意メッシュ遮蔽へ接続する場合は、ホストのdepth契約に合わせた拡張が必要。

透明面はtriangle単位で仮想深度順にソート。OITではないため交差面の完全な透明度解決を保証しない。専用画像テクスチャは使わないが、WebGPU framebufferとしてHDR color/depthのrender target textureは使用する。

`dispose()` でリソース解放。device lossはonErrorとstatsへ通知し、黙って別APIへフォールバックしない。再初期化はホストが行う。
