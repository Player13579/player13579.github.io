# r0.3 実機確認手順 / 機械検査と品質観察を分離

## 提出時

quality/report.json が現行の結果です。ブラウザ初期化を実際に試行しましたが、localhost遷移が管理ポリシーで拒否され、WebGPUへの到達前に停止しました。エラー記録は quality/browser-run/report.json。実GPU・WGSL実コンパイル・sampler実行・実H64描画・実聴・芸術的効果はnot_runです。P0/r0.1でユーザーが確認できた限定状態はr0.3の証拠ではありません。

## 起動確認

1. `npm start` でlocalhostを開きます。初期化失敗は画面のエラー表示とruntimeログに残します。GPUが使用できない場合、別方式の画像を表示して合格にしません。
2. GPU名、OS、ブラウザversion、DPR、ブラウザ倍率100%、画面寸法を記録します。adapter取得だけでは物理GPUでの描画を証明しません。software adapterならsoftwareと明記してください。
3. H64原寸で定規とproxyの高さが64CSSpx、2倍で128CSSpxになることを確認します。検査用proxyの遮蔽と、実ゲームのキャラ美術との遮蔽確認は別です。

## 5枝の時間連続性

シークの静止画だけで完了にしません。各枝を開始前から消去後まで連続再生してください。画面の最大actor時間ステップと相毎のフレーム数で見落としを記録します。

| 枝 | 開始〜中間で見ること | 保持・終端・消去で見ること |
|---|---|---|
| charge | 発動者の列が別々に捕獲・噛合い、単なる円状点滅ではない。 | 1200ms後はready-held。2.6sのresolveまで保持し、その後240ms以内に撤去。期限760msの別シナリオでは準備を勝手に完成させない。 |
| normal | sourceに残るだけでなく有限区間が移動。前端の前と後端の後が空。 | 180msの受信終端と520msの消去。70ms時点でresolveする別シナリオでは未到達targetが後から光らない。 |
| resonance | 二入力から中点の共有bridge/6接続路へ転換。通常2発や単一円環の加算ではない。 | 接続路の異なる退役と1600msの消去。相殺とは残り方が異なる。 |
| cancellation | 対向hook列が噛み合い、消費された上段と残る下段が併存。 | 前線通過後は空の境界へ。外へ同じ図形が膨らんで消えるだけではない。1600msで空。 |
| storage lock | targetへ追従してラッチ、背面棚は体の後ろ、前面ゲートは所定位置。 | 7.2sの旧期限を越えて8.6sの延長期限まで保持。延長で再ラッチしない。期限/resolve後280msで消去。 |

共鳴→相殺、相殺→共鳴、同時重なりを同じ背景・倍率で比較します。相手の枝、pair、source、midpointを入れ替えていないか確認します。早期解決済みの効果は既存形状の撤去だけで、新しいピークへ進まないことを見ます。d=0でもNaN、巨大な線、原点ワープ、架空の対象が出ないことを確認してください。

## 条件巡回

本プレビューは13シナリオ×2背景×2品質×2速度×2倍率×3遮蔽=624条件を巡回できます。各条件はシナリオの開始から空の状態まで再生します。UIの巡回完了は「時計を進めて記録した」ことだけです。処理落ちで欠けた相や、見ていない条件を観察済みにしません。途中でUI条件を変更した場合はその巡回を中止し、条件を固定してやり直してください。

明背景では白稜が消えず暗い形が残るか、暗背景ではbloomが面全体を白くしないかを見ます。High/Lowとも主要列数、方向、欠損順、保護された対象位置が同じかを見ます。MSAAを下げて形の意味を削らないこと、2倍速で薄い相が飛ぶことによる見落としを分けて記録します。

mixed/front/back遮蔽は同じ幾何のdepthだけを変えます。透明面のソートは近似のため、交差部・前後反転・halo・黒縁を特に確認します。rangeガイドはUI ONLYと表示され、画面上で見える輪郭から判定やダメージを推定しません。

## 実聴と発音数

音声ボタンで有効化し初めから再生。まず控えめな音量で確認してください。PCMピークが数値範囲内でも、音量やイヤホンで聞こえ方は変わります。実機で聴かなければ実聴statusを変更しません。

chargeの段階的起音→保持、normalの送信snap→受信clasp、resonanceの共有和音→分岐退役、cancellationの対向chirp→スペクトル消去、lockのラッチ→小音量保持→解除codaを分けて聞きます。起音・中間・終端・無音化を全て確認してください。

EVENT/AUDIO LEDGERのexpected causes、queued、worklet created/started/active、resolutions/extensionsを照合します。重複event、別id同cause、重複resolve、lock extendは新しいvoiceを増やさないことを確認します。codaは同じvoiceの終端なので、新しい攻撃音として聞こえないかを実聴で判断します。counterの増分だけで聴取合格にしません。

距離計測の基準を「有効音源からの距離（検査追従）」にして単独枝を再生します。「世界原点からのY offset」は必ずしも各音源までの距離ではありません。重なり時には複数音源の距離が異なることも記録します。距離d=0、中距離、通常2200/共鳴2600/相殺1800の直前と以上で減衰・無音化を確認します。ステレオ定位の中心と発生位置、2倍速の音高/時間、停止・再開時の二重起音やクリックも観察します。voice容量dropやclock staleがあればその条件を記録してください。

## 証拠保存

「実行ログをJSON保存」で条件・相・時間ステップ・binding/eventログ・GPU診断・音声統計を保存します。「実聴を行った」のチェックとメモは自己申告記録であり、自動品質合格にはしません。quality/manual-checklist.json に対象枝/時間区間/背景/倍率/adapter/音量/観察者/スクリーンショットまたは動画を紐づけてください。

任意の自動ブラウザ試験は tests/browser-smoke.py。Playwrightを検査側環境へ別途用意し、必要ならEMP_BROWSERとEMP_BASE_URLを指定します。既定は初期化smoke、--fullで全条件を連続巡回します。管理ポリシー変更・隠したsoftware adapter強制は行いません。headlessのAudioContext成功は実聴ではありません。

仕様の構造検査、幾何/波形の数値検査、実GPU描画、H64での意味認識、実聴、実ゲーム接続は別の受入層です。一つの成功を他へ転記しません。
