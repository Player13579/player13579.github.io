# r0.4 実機レビュー手順（採用判定とは別）

## 1. 原本と実行環境
元ZIPを保持し、検証コピーで `node tools/hash.mjs --check` を実行。Chromeのバージョン、OS、adapter vendor/device/description、fallback情報、ブラウザ倍率、devicePixelRatio、音声出力先を記録する。software adapterを実GPU品質に数えない。

ページのWGSLコンパイル・pipeline診断を確認。「初期化成功」は技術段階であり画質の合格ではない。エラー時は変更前のコード/ハッシュとログを保持。コードを修正したコピーの結果を元ZIPの成功へすり替えない。

## 2. H64の全寿命
暗明×1倍/2倍を連続再生で観察する。初期、内向き移送、受納、締まり、静止保持、消灯までを少なくとも数回見る。特にユーザー報告の区間 p=.035–.4 と .6–.9、終端.96–1を確認。追加の検査点17件は補助であり連続観察を置き換えない。

R03: 主形が細いリボン/軌跡/粒子列へ縮退していないか。R04: 後半の三室が平板/一様な矩形にならず、くびれ・丸み・芯/外層の差を保つか。R05: 外部残量の減少と身体側のQ増加が同じ場所・時相で読めるか。R06: 走行速度上昇や自然回復の反復に見えないか。

暗背景で白い塊化、明背景で輪郭消失を別々に見る。局所拡散をオフにしても主形・充填の因果が残るか。明背景で単なる光量増だけに頼っていないか。H160だけで見える模様をH64の証拠にしない。

## 3. 遮蔽と人物
人物メッシュの表示/非表示を切り替えてEの時相・寿命が変わらないことを確認。前腕を手前に置き、世界内の体積が腕の前後を正しく通るか、見えない発光がOBSだけで前へ漏れないかを見る。二人近接ケースで別playerIdへ発光・音が誤帰属しないか確認。

## 4. 時計・重複
1500/900 actor-msの各設定で確認。1倍と2倍で同じactor位相に同じ主形があり、2倍は壁時計寿命が半分になること。pauseで途中の形が維持されて音が止まり、再開で新しい起音が発生しないこと。

同じeventの毎frame再送: accepted/start/voiceは一回だけでduplicateだけ増加すること。独立180 actor-ms差の二件: Q、p、開始/終了、voiceが別であり、先行満了時に後続が跳ねたり延長されたりしないこと。2倍では180 actor-ms=90 wall-ms。4パネルによりvoiceが4倍にならないこと。

死亡・退出・ゲーム不可視・逆行・cancelを途中で注入し、同じID再送で復活しないこと。gain0/負値/natural-tickでEもSFXも開始しないこと。

## 5. 実聴
低めの再生音量から確認。起音がクリックでなく一回の柔らかい始まりに聞こえるか。移送から受納共鳴への音色移行が到達時相に結び付くか。2倍で包絡が短くなり音程を倍化しないか。終端が新たなチャイム/破裂/クリックにならず落ち着くか。取消時の最大8msリリース後に無音になるか。途中の音声解錠や音声時計切替で過去の起音がまとめて鳴らないか。

WAVの数値振幅・DC・tailが正常でも実聴の合格ではない。AudioWorklet実出力、機器、聴取条件を記録する。

## 6. 記録と判断
技術記録JSON、必要な実GPUフレーム/連続キャプチャ、実聴メモを同じ検証コピーのハッシュへ結ぶ。`verification/REVIEW_TEMPLATE.json` の各not_runを、実際に行った範囲だけ更新する。`supported/uncertain/contradicted` を具体的な証拠と結ぶ。

単フレーム、行列描画の完了、CPU数値テスト、自己評価で全寿命画質をPassにしない。品質採用・本編接続の承認欄はユーザーの明示承認まで変更しない。
