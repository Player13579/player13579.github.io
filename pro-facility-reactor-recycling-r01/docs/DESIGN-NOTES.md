# 独立した2件の設計

## A: reactorGauge / luckBoost

源は開いたゲージの境界と針です。針の動き、開口、供給ピークが対応し、内部を一つの白い円で塗りません。源が励起した提示用fieldは幅を持つアーチ状の帯として進み、先端/後端と内部の低密度筋で輸送を示します。受け手の実座標では、帯の到達後に二つの開いた輪郭が増分の受領を示します。

時間はA専用の5次補間で、源の立上り、帯の進行、受領の立上り、表示の終了を別の窓にしました。密度の峰と放射の峰は同一変数ではありません。source-bound応答を無効にしても、源のゲージ、帯内部、受け手の二つの輪郭はshaderに残ります。ただし実画素を観察していないため、H64でその手掛かりが十分かは未確定です。

色は深い青緑の内部、青・シアンの輸送、黄緑の源/受領を役割別に使用します。音は低い倍音の立上りから周波数が上がり、到達相に協和成分が加わる一つの1720ms音です。これを「幸運が物理的に伝わる現象の実証」や、+0.15の実測成功率として扱いません。

## B: recyclingUnit / credits

源は二つの平行な圧縮境界と側部です。間隔の変化、暗い内部、明るい切断縁が作用を示します。3区画の押出しは、開始時刻と到達時刻を別に持つ有限な長方形です。ばらまかれた粒子や実物の硬貨を追加せず、同じ提示fieldの3つの状態区画として扱います。

各区画が到達すると受け手の横に着座し、間隔を保った3区画が成立します。終端はAの輪郭減衰とは異なり、矩形の幅が閉じます。B専用のcosine包絡と時間差付きの進行を使い、Aの時間関数を流用していません。

色は圧縮域の赤褐色、搬送の銅橙、着座縁の淡い琥珀です。音も連続した開口音ではなく、短い圧縮の擦過と3区画の着座を一つの1620ms音へまとめました。サーバーのクレジット+3は即時という指定を保持し、着座はその後の確認表現です。UI/VFXの到達がクレジットの付与を起こす設計ではありません。

## 共通の観測設計

PH1/2/3はゲームの提示worldに属する源/輸送/受領です。サーバー経済状態や人体・設備の物質状態と同一視しません。OBS1は源に束縛した狭いにじみ、OBS2は既存境界の分離、OBS3は表示変換、OBS4は一回の確認音です。

強い発光はHDRの局所源として維持します。白飛び回避のために源の出力を一律に弱めるのではなく、主形の内部の抜け・暗い輪郭・表示の肩を別に用意しています。実際にどこまで白化するか、明背景で暗い輪郭が十分かは実GPU画素で確認する必要があります。

物理レンズの面、開口、内部反射経路は宣言していないため、ghost/veil/streakを追加しません。狭いPSFは表示上の近似として記録し、特定カメラの実測応答とはしません。粒子、発光を隠すための背景暗幕、scanline、grain、速度線、露光残像、魔法presetは使っていません。

## reduced motion

弾道・飛行・身体反応を追加せず、輸送の因果に必要な進行は残します。Aは帯の横方向の張出しをなくし、Bは圧縮の移動量を減らします。繰返し振動、点滅、カメラ揺れを設計していません。これは完全な無動作モードではありません。ユーザーの端末のreduced-motion設定をpreviewで初期読取し、ホストには明示引数で渡せます。

## 成功と棄却

コードの存在、native再生、層数、数値テストの数は視覚品質を保証しません。全寿命を原寸で見て、起点/作用/結果の欠落、3区画の潰れ、色替えだけに見える類似、glowを切ると主形がなくなること、受け手の誤認、二重発音があれば棄却します。原因については観察事実と仮説を分け、旧版の造形・コードを参照して推定原因を埋めません。
