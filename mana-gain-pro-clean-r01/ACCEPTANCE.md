# 受入基準と未実施の検査

## 判定の単位

構造・契約テスト、WGSLコンパイル、GPU提出、実画素、動き、聴感、ゲーム統合、芸術的効果を別に判定します。設計のtrueは要求値です。結果はvalidation/report.jsonだけに記録します。画像・動画・音の観察をしていない項目はnot_runのままです。

既存Mana Eは参照・比較しません。旧版の「H64で小さな浮いた青い弧や接触線にしか見えず、到着と蓄積が読めない」をこの候補の不合格条件としてのみ使用します。

## 自動テスト

Node検査は、確定正増加だけの受理、全除外条件、同じIDの再受信、ID/受け手の衝突、現在位置への追従、非表示・死亡・退場・ベント・透明・失効・別scope、GPU失敗、古い非同期proof、ミュート・verify・AudioContext未稼働、ACC2の1→2→1連続積分、SFXの一回start、WAVの再現性と無クリップ、PH/OBS構造を対象にします。

JavaScriptの構文検査はWGSLのコンパイルではありません。Bの独自構造テストも、ユーザー側の正式なB検証器の合格ではありません。

## GPU・実画素の検査

/tests/browser.htmlを開き、compile informationにerrorがないこと、pipeline作成、queue提出、readbackの各成功を確認します。adapter、ブラウザ、OS、DPR、表示倍率、canvas rasterを記録します。自動検査は暗/明背景でp=0〜1を0.02刻みに102フレーム描画します。

計測の最低基準は、p<0.94で無画像にならない、p=1で背景と完全一致する、描画領域がE枠の投影に収まる、初期は足元の差分が大きく、受領時は体幹の差分が大きい、重心が足元から体幹へ進むことです。しきい値は本候補の検査用であり、普遍的な美的合格基準ではありません。

加えて、p=0.00 / 0.12 / 0.28 / 0.44 / 0.50 / 0.62 / 0.74 / 0.88 / 0.96 / 1.00をH64実寸で観察してください。拡大版だけを見て合格にしません。閉じた可視源、有色で厚みのある輸送、到着後の受領面積・充填増大、中心を保つ収束が必要です。

弧や接触線だけに見える、受領前から体幹が満ちる、源との関係がない飾りに見える、同じ菱形がただ点滅する、粒子上昇だけ、全面均一glow、白い塊で主形が読めない場合は不合格です。明示された局所白飛びはそれ自体を不合格にせず、有色主形・因果・受領域の読みを保っているかで評価します。

## 時間・動き・同時発生

通常1倍、最初から実効ACC2の2倍、待機・予約・activeだが非実効、途中1→2→1の各条件で全寿命を観察します。切替で位相や形が巻き戻らず、源・受領・光・SFXが同じE時間に従うことが必要です。別ownerの速度が混ざる場合は不合格です。

同じ受け手に異なる3件、異なる受け手に2件、同じIDを再受信、近接して片方だけ退場、片方だけ別session、GPU fence待機中のprivacy変更を検査します。id単位のSFX回数、受け手位置、終端を照合します。64件上限での負荷測定は別項目です。上限外を無制限に保証しません。

reduced motionでは横方向の曲がりを減らすだけで、源→受領の意味を消しません。無指定の点滅や装飾揺れは元々ありません。副次拡散が縮小で消えても、主形が読めることを優先します。

## SFX聴感

初期ミュート、音の有効化前、AudioContext suspended、非表示、verify、ルーム/session切替時に無音であることを実機で確認します。音有効時も、可視frameの同じevent idについて一回だけ鳴り、終端以後にループ・遅延再発音・残響voiceが続かないことが必要です。

1倍・2倍・途中切替で、発生音→輸送→受領和音→収束尾部が視覚と対応して聞こえるかを評価します。2倍は音高も上がる方式です。急なrate/voice数変更でクリック、耳に痛いピーク、濁り、時間ずれがあるかを聴取してください。複数同時時の音量正規化は実装済みですが、快適さや聴感の良さは未検証です。

WAVのpeakや決定的再生成テストは聴感評価ではありません。実際の聴取者、出力機器、音量、条件、感想と問題点を記録してください。

## ゲーム統合とB正本

実ゲームの確定gain通知から接続し、実キャラ・床・壁・カメラ・不可視条件・実効ACC2イベントで検査します。この候補はネイティブゲームAPIに未接続です。プレビューの擬似通知をゲーム統合テストの成功に数えません。

Bのcanonical source_commit/base_blob/extension_blobを正式に受領して固定するまでは、この部分の条件は未完了です。candidateのmanifest/hashはその代用ではありません。E設計記録はBを新modeへ変更せず、画像・動画生成の権限を持ちません。

## 記録テンプレート

観察者、日時、ブラウザ/OS/GPU、DPR、表示倍率、背景、世界尺度、ACC2状態、同時event数、音声出力、確認対象を記録します。各項目をpass / warning / failed / not_runで記し、画素または録画・聴取メモの実在する参照を付けます。未観察の項目を他の項目の合格から推測して埋めないでください。
