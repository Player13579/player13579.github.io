# 状態契約 / mana-gain/4

## 権威・所有

正の資源増加がすでに確定した後だけ `commit` します。有限正値のmanaDeltaとcommitted=trueを要求します。VFXの吸収相は資源確定を遅らせたり、そこで再加算したりする処理ではありません。

beneficiaryPlayerIdは配置・身体形状・生存可視性の所有者、actorPlayerIdは原因の時計所有者です。一致してもよいが、暗黙に同一人物へ置き換えません。

## 台帳

VFXは `[sessionId,eventId,beneficiaryPlayerId]`、SFXは `[sessionId,eventId]` で識別します。JSON tupleで符号化し、ID中の区切り文字で衝突しません。同じ原因の複数受益者は複数VFX・共通の一声。独立3原因は3声です。

無効入力はrejected。正しい通知でも身体不可視、期限済み、容量超過、受容ポリゴン無効ならsuppressedとして消費し、後で身体が戻っても同通知を復活させません。同原因のactor・寿命・開始時刻変更は拒否。消費済み台帳はセッション内で勝手に失効させず、容量超過時は古いIDの破棄ではなくfail-closedです。

## actor時間

年齢は `actor.timeMs-startActorMs`、既定1500 actor-ms、最低900 actor-ms。timeMsへrateが反映済みなので、年齢へもう一度掛けません。2倍で1500 actor-msは750 wall-ms相当になります。SFXは同じactor位置とrateに同期します。

| 正規化相 | 1500msの範囲 | 読ませる関係 |
|---|---:|---|
| 0–0.22 | 0–330 | 身体外の供給本体。二つ目は遅れて現れる |
| 0.22–0.42 | 330–630 | 身体境界を越える流量と、接触変換の局所光 |
| 0.42–0.67 | 630–1005 | 外側の量が減る間、身体ポリゴン内の充填面積が増える |
| 0.67–0.84 | 1005–1260 | 充填済み状態と身体輪郭の短い応答 |
| 0.84–1 | 1260–1500 | 可視光とcoverageが低下。保存済みの量は減らない |
| 1以上 | 1500以上 | Eインスタンスを削除し描画頂点ゼロ |

表の境界で新イベントを起こしません。連続関数が相をまたぎます。900msでは同じ正規化関数を0.6倍のactor時間で評価します。

## 供給・受領量

各原因のマナ量を表示設計上の正規化量Q=1として扱います。実ゲームのmanaDeltaの数値を面積で厳密に比較表示するものではありません。二経路の配分は0.62／0.38という今回の設計値です。

各packetの通過率から受領量Qinと流量dQin/dpを求め、外側残量Qout=1-Qinにします。身体の凸ポリゴンを斜めの半平面で切り、面積比がQinになる境界を22反復で解きます。これは数値設計上の一致であり、魔法の物性を実測したものではありません。有限幅のmesh描画・遮蔽・coverageは量の厳密な画素カウントとは別です。

Qinは単調増加し終盤でも1を保持します。Eが消えることは獲得マナが失われることを意味しません。色・bloom・表示変換はQの台帳に影響しません。

## 終了条件

期限、生存false、在室false、ベントtrue、透明true、身体欠落／形状不正、時計欠落／不正／巻き戻り、明示cancel、セッション変更、disposeでEを消します。causeの最後の受益者が消えると音もcancel。別の受益者が残る場合は一声を維持します。

復帰だけでは再点灯・再起音しません。プレビューの「新しい原因で再生」は別IDを発行する検査操作であり、統合APIの自動挙動ではありません。消去時はrenderer.invalidateと通常のフレーム再描画も必要です。

## 検証範囲

状態・正規化量・ポリゴン面積・PCM開始数はNodeテスト／offline計算で検査します。実スキンの知覚、GPU描画、音響機器の遅延、快適な音量、実ゲームの権威イベント配送は別の検査です。
