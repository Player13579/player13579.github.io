# r0.4 設計 — 外流・境界変換・輪郭充填

## 入力として扱った失敗

ユーザーはr0.3の原本WGSLを技術adapterで修正してChrome実WebGPUを確認し、H64／2倍／3倍で「胴内の緑青色の平たい楕円」に見え、外からの供給と身体の受容・充填が読めないと報告しました。この報告は全寿命観察を意味しません。r0.2の楕円挿入・弱い発光・平板終端の報告も、改稿課題として保持します。

今回、旧版のファイル・画像・音・shaderは読みませんでした。旧案の形を別名で装飾するのではなく、外側／境界／身体内のgeometryと、通過量に基づく連続関数を新しく構成しました。

## 三つの場所と一つの量

**外側**：左下の遠側帯と右上の近側帯が有限の量を運びます。対称な外肢にならないよう、幅・向き・開始・量の配分を異ならせています。線一本や粒子列ではなく、幅8–10.5 game pxを持つ有色の面と暗い内部、細い強放射の頂部で構成します。これらの値はH64向けの設計値で、物理実測ではありません。

**境界**：帯のmeshから身体受容ポリゴンを差し引き、元の物体形状を身体内へ描きません。供給が境界へ到達する前から接点が無関係に点灯することを避け、通過流量が正の間だけ暗い支持線と高輝度の変換縁を出します。背面の帯は身体で遮蔽し、前面の帯と接点はホストの前景より奥へ置きます。

**身体内**：受領量と同じ割合の面積を身体ポリゴン内に生成します。形は身体の輪郭を継承し、胸の中央に独立した楕円・コア・バッジを増やしません。斜めの充填前線と広い面の応答で受容済み領域を区別します。装飾的な細かい帯の反復で「多層」を水増ししません。

供給残量と受領量は一組の連続関数から出します。相名の切り替えで外側を消して別の図形を出すだけではありません。定着後は受領量を維持し、発光とcoverageのみを下げます。終端でも既存身体の面・辺が応答の所在であり、小さな灰色楕円や白点へ収束させません。

## 光と観測

源の放射係数はlinear HDRで3.6、接点は4.1を上限係数とする設計です。これらは最終pixelの輝度保証値でもcd/m²でもありません。meshの面積、alpha、局所プロファイル、重なりが最終出力に影響します。

本体色、放射、暗部は別々です。材質をsource-over、放射をaddで`rgba16float`へ保持します。局所bloomは放射だけから作り、body polygonや主形の代わりにしません。9tapの横／縦filterで、stepは0.60 game px、混合係数0.42。背景画素を入力にした効果の分岐はありません。

表示変換はRGB peakが0.82以下では線形値を変更せず、それを越えるHDR peakだけを滑らかに圧縮しRGB比を保ちます。これは全源を弱くする一律減光ではありません。一般にどんな表示器でも同じ知覚になるとは保証しません。bloomを切っても供給・境界・身体充填のmeshが残ることを検査できる構成です。

## 多層の責務

PH1は既存身体、PH2は有限のマナ供給、PH3は境界変換、PH4は受領状態です。同じPH2の内部色・発光縁を学問別にPHへ分割しません。VFXの層は供給、変換、身体充填、局所身体応答、観測補助を役割で分けます。層数を高度さの点数としません。

OBS1はraster／coverage、OBS2は源依存bloom、OBS3は表示変換、OBS4はゲームSFXです。SFXは指定されたフィードバック音であり、魔法の空気振動を測定したと偽らない観測出力です。詳細なB-Expression-2インスタンスは同フォルダーのJSONにあります。

## SFX

一つのvoice内で、短い非整数倍音の起音から、受領量に応じた倍音の収束とステレオ幅の縮小へ進みます。境界流量と受領量を映像と同じsamplerから取得します。視覚の各層から別の音符やvoiceを起こしません。2倍actorではPCM位置が2倍に進むためピッチも上がります。音の快適さ・固有性・出音品質は未試聴です。

## 未解決の知覚リスク

CPU参照では楕円の主形がなくなり、外側の二帯・境界・身体面の増加が別領域に現れています。ただし、帯が刃・飛来弾に見える可能性、身体充填が服の着色やUIに見える可能性、3原因で充填面が重なる可能性は、実GPUと観察者の判断を要します。CPU画像の見え方だけで「マナ獲得が一目で伝わった」とは結論していません。
