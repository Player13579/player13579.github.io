# 動作確認手順

## 0. 配布物の固定

展開直後に `npm run verify`。その後 `npm test` と `npm run validate:design`。Nodeテストはロジック・PCM・モックdescriptorの検査であり実GPU検査ではありません。診断成果物の再生成・ログ更新後は配布時ハッシュが変わるため、既存manifestの書換え前に差分を確認してください。

## 1. ブラウザー手動確認

`npm start` で起動し `http://localhost:4174`。WebGPU adapterの表示、コンソール、uncapturederror、shader compilation情報を確認します。CPUのgallery画像をプレビューの実GPU出力と混同しません。ソフトウェアadapterの場合はsoftware WebGPUとして明記し、実ハードGPU検証に数えません。vendor等が非開示ならhardware種別は不確定です。

初期画面はH64／H128／H192 × 暗／明です。各倍率のキャラクター高さが64／128／192 CSS pxであること、表示ズーム100%を確認します。画面距離・DPR・解像度・OS・ブラウザー・GPU・表示倍率を記録してください。背景ごとに色や形を調整する設定はありません。

まず単発、1500 actor-ms、1×で発生から消去後まで連続再生。次に2×、近接3回1×、近接3回2×をそれぞれ繰り返します。900msにも切り替えて同じ正規化相が保たれることを確認します。単発と3原因の最終終了は1×1500／1820 actor-ms、2×のwall時間は750／910msです。各群後の空白はプレビュー用600 actor-msで、Eの寿命ではありません。

無音スクラブで0、90、210、400、600、820、1060、1260、1380、1460、1490、1500、1600 actor-msを比較します。3原因では1740、1810、1820、1900も確認します。スクラブはモックの専用標本であり、本編イベントを巻き戻す操作ではありません。静止画だけで時相の成功を判定せず、必ず連続再生も見てください。

前景遮蔽をONにして、遠側E→身体→前側E→前景の順序を調べます。頭部にマーカーが出ないこと、身体が透明・退室・死亡・ベントの状態に変わるとEが消えることを確認します。身体復帰だけでは再発火しません。「新しい原因で再生」は新セッションの別モック原因です。

## 2. 音

「音を有効化」はユーザー操作が必要です。ロック中に発生した原因は、その後の解錠でも後追い再生しません。有効化後に「新しい原因で再生」を押し、単発1声、近接3回3声をUIカウンターと実音の両方で確認します。UIのaccepted累計は過去の群も含みます。Workletの開始数・現在声数・最大同時数は実Workletから返された場合のみ表示します。

2×はPCMのactor-time参照速度も2×なので、時間とピッチの両方が変わります。ピッチ保持の時間伸縮は実装していません。起音から変換相への連続性、吸収時の倍音整列、音像の収束、低明度終端に対応する小音量、消去後の無音を聴きます。複数の原因に属する音を一声に間引くことも、相ごとに起音し直すこともありません。

一時停止はactor rate=0、VFX保持、音はDC音を出さず無音。再開と1×→2×の途中変更を確認します。消去操作は4msの音側終了処理を持ちます。機器上のクリック、遅延、音量や聴感は数値テストだけでは採否しません。

`audio/`の4 WAVは同じ合成器＋VoiceMixerのオフライン出力です。比較試聴用であり、AudioWorklet実稼働の録音ではありません。ギャラリーのCPUクリップに重ねた音も同じです。

## 3. 実ブラウザー自動ハーネス

別途Python版Playwrightとブラウザーを利用できる環境で、`python tools/browser-check.py --url http://localhost:4174 --executable /path/to/chromium`。`--headed` は可視ブラウザー、`--video` はPlaywright側ffmpegが導入済みの場合だけ指定します。`--software` は明示されたソフトウェアWebGPU検査でありhardware受入とは分けます。通常プレビューにPlaywrightは不要です。

ハーネスは全6ビューの相別キャプチャ、1／3原因×1／2rate×1500／900msの連続実行、前景、全消去条件、音開始数を記録します。ブラウザー動画収録を有効化した場合はキャプチャ側のcadenceにも制約があるため、実行時刻ログと合わせて判定してください。ハーネス自身は絵の意味や音の聴感を自動判定しません。観察者が画像・動画・音を実際にレビューし、証拠参照を付けて `docs/QUALITY.md` の条件を評価します。

結果は `qa/browser-run.json` と `qa/browser-capture/`。配布記録を保存してから再実行してください。管理ポリシーで遮断された場合はその状態を記録し、組織ポリシーを回避しないでください。

## 4. 実ゲーム統合前の追加検査

`src/index.js` のAPIだけをホストに渡し、`preview/`を取り込みません。本編配線は未承認です。承認後も、実際の権威イベントの正値・順序・ID、actor-time連続性、受益身体のroot/manaAnchor/contactScale、身体mask・前景、ミキサー、セッション境界、device loss、休止復帰を別途確認する必要があります。プレビューでのモック成功を実ゲーム合格にしません。

ホストのactor時間が過去へ戻った場合は既存Eを破棄し、その原因を巻き戻し再生しません。ホストが同一原因を複数受益者へ通知してもSFX一声を保つこと、死亡した受益者だけを消して他受益者の同原因表示を誤消去しないことを検査します。大量イベント時の上限抑止は状態契約を参照してください。
