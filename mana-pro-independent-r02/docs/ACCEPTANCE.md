# r0.2 受入・棄却基準

## 最上位の棄却条件

**H64原寸の暗・明双方を、源の出現から収束・消失まで通して再生し、足元の源→腹部への輸送→受領量の蓄積という三段階が連続して読めなければ棄却する。**

中央の物体が光るだけに見える、輸送の経路が一瞬しか分からない、到着前後の量が区別できない、説明文や拡大/スクラブでしか理解できない場合は、この条件を満たさない。細線・粒子上昇・均一glowで不足を覆うことも合格にしない。コードの複雑さ、PH数、規則表の件数、画素数の閾値は代替の合格点ではない。

r0.1の不合格原因は未特定のまま保持する。r0.2の評価は、採用形のH64全寿命で行う。特定パラメータが悪かったと先に結論づけない。

## 観察条件

プレビューをH64、ブラウザー倍率100%、位相案内なしで再生する。暗・明をそれぞれ見る。両背景を同時に見た印象だけで片方の失敗を見落とさない。DPR/Chrome版/画面倍率/OS/機器を分かる範囲で記録する。身体なしの候補を実身体の合成確認済みとはしない。

1×の単件全寿命を先に確認し、その後2×、途中切替、近接する異なる三件を確認する。H128/3倍や層分解は原因候補を探る補助であり、初回の意味読解判定に代用しない。

| 段階 | 観察すること | 棄却する見え |
|---|---|---|
| 源 | 足元に面と局所発光があり、供給元を一目で特定できる | 小点/細い接触線/浮いた弧だけ |
| 輸送 | 源から受領域へ進む方向と接続を追える | 単純な粒子上昇、唐突な瞬間移動、経路が消える |
| 受領 | 到着と同時に、腹部位置の充填/面積/残量が増える | 定常の小物の点滅、到着しても量が変わらない |
| 保持 | 輸送終了後に受け取った状態が残る | 通り抜けて消えるだけ |
| 収束 | 同じ受領中心へ縮み、光域も終端へ閉じる | 受領体が消えたあと広いglowだけ残る |

開始前や完全消失後は空白でよい。ただし中間の引渡しが読めないことを「その相は省略」として合格にしてはいけない。

## 技術契約の検査

正の実確定増分一件に一回の表示、ID重複の拒否、0/負値/上限無変化/自然回復/錬気の除外を確認する。現在受け手位置へ追従し、死亡・退場・ベント・透明・失効・別context・画面外・非表示で視覚と音を止める。消えたEが再表示や非ミュート化で遅れて再発火しないことを確認する。

durationの正本は1.6所有者秒。移動ACC2実効activeの間だけ2×、待機・予約・OFF・非移動は1×。途中切替で巻き戻り、段飛び、SFXの再startがあれば不適合。同じIDを暗明の二画面に表示しても音は一回。

初回発音は、実canvasのGPU提出成功・主形token・epoch・現在可視性の確認に対応しなければならない。ミュート/verify/AudioContext非runningで鳴らさず、ルーム/セッション変更で旧音を破棄する。模擬プレビューの予約callbackも旧sessionから新sessionへイベントを漏らさない。

## SFXの聴感

最初は控えめな音量で、単件1×→2×→途中切替→近接三件の順に確認する。発生、連続輸送、到着・満量、終端の音の変化が視覚と対応するかを聞く。クリック、途中の再打音、余計な二重発音、終端後の残響、過大な音量、映像とのずれがないかを記録する。playbackRateによる音高変化は継承した仕様であり、意図しないピッチ飛び/再発音とは区別する。

波形のピーク/端点/WAV一致のPassは、聴感のPassではない。AudioContextや物理出力デバイスの遅延は未測定。実デバイス試聴がない場合はnot_runとする。

## 同梱の自動検査が示す範囲

Nodeテストは状態・ID・時計・発音mock・波形・解析形状を確認する。CPU解析場の161位相では面積、重なり、連結成分、終端、OBSなしの本体を検査する。CPU負対照の小さな中央定常形がこれらの代理条件を満たさないことも確認する。この負対照はr0.1の見た目の再現や原因分析ではない。

`tests/verify.html` は実WebGPUで161固定位相、層分解、画素数、包絡、終端を確認する。処理成功は技術上の検査であり、全寿命を自然な速度で一目で理解できるかの判定とは別。GPUの固定位相サンプリングは実rAFのcadenceやディスプレイ走査を測定しない。

## 記録の書式

`version / evaluator / device / Chrome / DPR / browser zoom / H64 / background / rate / event count / cue / time range / supported|uncertain|contradicted / evidence reference / notes` を記録する。評価の根拠がない項目はnot_run。未確定の原因は仮説として分け、実画像や比較記録なしに因果を断定しない。

納品時のr0.2は実GPU・聴感ともnot_run、品質は未受入。実ゲーム導入も未実施。
