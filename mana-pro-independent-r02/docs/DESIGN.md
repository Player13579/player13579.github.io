# r0.2 設計 — 連続した輸送面と充填境界

## 起点となる観測と、未特定の原因

ユーザーがr0.1をChrome WebGPUでH64原寸・暗明両背景・全寿命再生し、技術再生成功と品質未達を報告した。主に中央の小さな六角発光体が見え、足元の源→腹部への輸送→蓄積を一目で読めなかった、という観測を保持する。

この記録だけから特定の色、サイズ、時間定数、shader行、GPU挙動を原因と断定しない。r0.2は原因を一つに特定した修理ではなく、複数の造形・位相をまとめて変更した**新しい設計仮説**である。良くなったか、どの変更が効いたかという実比較は未実施。

## 採用した主形

足元の源は、面を持つ横長の供給域とする。輸送は点や独立した浮遊核ではなく、源と受領域を結ぶ一つの厚い面とする。受領は宝石の恒常発光ではなく、到着に対応して下から上へ増える面とする。新しいアイテム、容器、人形、魔法陣、文字、粒子、装飾輪を追加しない。

| 単位 | 状態・境界 | 画面で保持する根拠 | 主な実装 |
|---|---|---|---|
| PH1：供給 | (0,−5)wu、最大86×26wu。残量Sで半径とdensityが変わる | 横長の有色面、出口側の局所放射、排出に応じた面積低下 | `sourceField`, `sourceShape` |
| PH2：輸送 | (−24,−6)→(−13,−55)wuを結ぶ湾曲した面。全幅23〜28wu | 源と接続する前端、到着後も残る面、供給終了後に回収する後端 | `routePoint`, `ribbonInfo`, `transportField` |
| PH3：受領 | (0,−61)wu基準。底部+18wu、高さ8→44wu、半幅22→34wu | 充填上端の上昇、面積増加、輸送終了後の保持、同じ中心への収束 | `receiverShape`, `receiveField` |
| PHの放射応答 | 各PHの現在位置/量に結んだ有限光域 | source/transport/receiveの空間・時相に応じて周辺に届く光が変わる | `lightField`, `sampleLightAtWorld` |
| OBS1 | 入力PH近傍の狭い表示拡散 | 主形内部を保護し、光源が縮めば拡散域も縮む | `observe` |
| OBS2 | linear合成→sRGB、premultiplied alpha | 暗明で同じ形と色を提示する。背景の見えを世界の床と偽らない | `fragmentMain`, `present.wgsl` |

中軸を16分割して距離を評価するが、その線分自体を描画するのではない。半径を持つ面の合併として太い本体を作る。暗い区間にも不透明な有色面があり、明度crestの間が空間的な断裂にならない。

受領面は到着以前に空の器として出さない。量に応じて上端と幅が増える同じ領域で、内部に広い明度帯を持つ。頭・手・脚などの代用身体は作らない。腹部位置との結び付けは現在foot centerからの相対座標であり、実スプライトに重ねて身体への到着が伝わるかは未検証の別条件である。

## 共通時計と受け渡し

実行時正本は `EFFECT_DURATION_SECONDS=1.6` 所有者秒。下のuはその正規化値で、別durationや独立したSFXタイマーではない。

| 区間/境界 | u | 設計上の働き |
|---|---:|---|
| 源が可視 | 0から | 最初の主形tokenを持つ可視フレームで表示と時計を開始 |
| 前端の進行 | 0.02〜0.30 | 源に接続したまま受領域へ延ばす |
| 源量の排出 | 0.08〜0.62 | source面を縮め、輸送量へ割り当てる |
| 到着・充填 | 0.30〜0.76 | 前端到着と同時にRを増やし、面積とdensityへ反映 |
| 後端の回収 | 0.62〜0.76 | sourceが空になってから、同じ経路を受領側へ畳む |
| 満量の保持 | 0.76〜0.84 | 移動で終わらず、受け取った状態を残す |
| 収束・減光 | 0.84〜1 / 減光0.90〜1 | 同じ中心へ縮め、光域と強度も縮め、u=1で完全消失 |

S=1−smoothstep(0.08,0.62,u)、R=smoothstep(0.30,0.76,u)、T=max(0,1−S−R)。S+T+R=1は有限な**表示量**の分配であり、実際のmana値・質量・エネルギーの計測ではない。Eを再生してもmanaを増やさない。正の増分の大小に比例する量表示を保証するものでもない。

全寿命の連続性とは、源から輸送、輸送から受領、受領から収束への手掛かりを途中で失わず追えることである。終端u=1は消失する。実際には未到着なのに蓄積を先行表示したり、空になった源を説明用に永久点灯したりして「常に三つ見せる」ことはしない。この記述をH64での読解不成立の免責には使わず、最終判断はユーザーの棄却条件による。

途中ACC2切替ではOwnerClockがそれまでのrateで区分積分し、以後だけ1/2を変える。描画は所有者u、SFXは同じ一回限りBufferSourceのplaybackRateで追従する。待機・予約・OFF・非移動は1。音高も変わる速度変更を継承し、ピッチ維持処理は追加しない。

## 発光と材質の区別

densityは不透明度の指数応答へ、coverageは幾何境界へ、emissionは局所の放射へ使う。色面と放射を単一のalpha/glow値で代用しない。供給の琥珀色、輸送の青緑、受領の深い青緑/ミントを空間と時相に結ぶ。均等な虹色帯や無関係な輝点を足さない。

OBS1のalphaは `min(0.10, peak×0.38)×(1−coverage×0.86)`。中心を白いにじみで埋めない。PH3の収束ではlight半径をsqueeze、強度をsqueeze²に従わせる。細い本体が消えたのに大きなglowだけ残る末尾を避けるための**r0.2内の設計**であり、r0.1の原因診断ではない。

既存sourceが出す入射光は、無人物ギャラリーの中性診断表示へ提示する。実ゲーム材質へは `sampleLightAtWorld` を既存の照明パスで使用する必要があり、透明canvasを重ねただけで実キャラが光を受けたとは主張しない。外部光源の鏡面反射ではないためReflectionClosureは不適用理由を保った空mappingとする。実レンズのghostも追加しない。

## H64、身体、媒体

128wuを64CSSpxとするr0.1の設計換算を維持する。包絡はx±66、y−127〜+13wu。DPRはbacking storeにのみ反映し、CSSのH64を勝手に拡大しない。sourceは最大約43×13CSSpx、輸送は約11.5〜14CSSpxの全幅、満量受領は約34×22CSSpx。これらの寸法・面積は可読性の代理条件で、認識成功を保証する万能閾値ではない。

Bの右手座標とm表現は1wu=1/80mという設計換算で保持する。ゲームy下とBのY上の符号変換、正射影、画面y下を連続させる。Gravityとcalm airのWindCapsuleは保持するが、非物質の場へ空気抵抗・弾道・濡れ・熱変形を捏造しない。

## 拡張の起動

VFX/ECodeImplementationを使用する。選択したsource-boundなPostEffectsは属性具体化として `ordinary_posteffects=false`。LDMはこのEの発光と時相を扱い、共通IntensityBudget/SamplingContractを参照する。色相の役割分担はGradientAnchorPolicyに記録する。

「マナ獲得」からMagicArchitectureや魔法preset一式を起動しない。人物/身体の新規描画、登録キーワード、Video生成はないため対応モジュールは省略する。正式B JSONは引渡し時点u=0.47の `mode=Image / operation=design_only`。これは画像生成命令ではなく、実行可能Eの設計表現である。Eの時計はECodeImplementationに結び、Video既定10秒を混入しない。

## 確認したことと、確認していないこと

CPU参照は同じPHASE/GEOMETRYを使い、供給・輸送・受領の接続、受領面積の単調性、終端、OBSなしの主形を検査する。`src/geometry.mjs` と証拠PNGは検査専用であり、WebGPUが使えないときのfallbackではない。CPUとWGSLの数式は対応させたが、同一画素の実測一致は未確認。

WebGPU shaderコンパイル・実画素・実時間の動き・聴感・ゲーム合成はnot_run。数値試験と完成ソースの存在を、H64での因果読解成功へ読み替えない。
