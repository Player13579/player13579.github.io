# r0.3受入・棄却条件

## 品質の棄却条件を先に固定する

**H64原寸、暗・明のそれぞれ、発火から完全消失までの通常再生で、説明なしに源・途切れない輸送・受領と受領側の変化を見分けられない場合、品質を棄却します。** どちらか一方、一部の時間帯だけで読めた場合も合格ではありません。拡大図、CPU接続判定、正のwitness、shader pass、静止画の成功、説明を読んだ後の納得で代替しません。

開始/完全消失の外側にEがないことは正常です。active phaseで前端がまだ到着していないときは空の受領領域、供給後は受領済みの状態として、同じ因果の関係を追える必要があります。最初から最後まで同じ流れが常時発生しなければならない、という意味ではありません。

## 無説明の観察手順

最初はREADMEの造形説明、層名、CPU contact sheetを見ずに、通常プレビューの1×、暗明、位相案内なしで「1件再生」を観察します。初回は音をミュートしたまま視覚を判断します。何が起きたように見えたか、どこからどこへ移ったか、どちら側に何が増えたかを観察者自身の言葉で記録します。事前に「ここが源です」と部位を教えた観察は無説明条件ではありません。

次に全寿命を繰り返して、断裂・小図形への分離・受領の位置飛び・終端にglowだけ残る区間を記録します。等速、実効移動ACC2、途中でactive→待機/OFF→activeとなる条件を別々に確認します。2×/4×、スクラブ、層分解は失敗位置の調査に使えますが、合格条件には使いません。

初回報告と説明後の報告を分け、Windowsの表示倍率、Chromeバージョン、DPR、キャンバスCSS/bufferサイズ、再生時のフレーム間隔、背景、音の有無を記録します。複数観察者がいる場合は提示順による学習や背景順序も記録します。成功率や有意差を、反復なしで作りません。

## 技術ゲート

`npm test` / `npm run check` / `npm run check:field` がpassでも品質欄は未観察のままです。GPU検査ページはshaderコンパイル、実GPU提出、色付き本体のwitness、3点の背景差、CPU式との数値差、代表位相の本体接続、受領面積の変化を記録します。161位相は有限の標本であり、連続動画の全時間を証明しません。

H64原寸の再生が成り立たない、意図せず拡大/縮小された、未対応WebGPUが別方式で描かれた、GPU失敗後に音が鳴る等は技術面で棄却します。GPU/DOMの成功receiptはブラウザー内の確認であり、OSの実scanoutや別ウィンドウによる遮蔽を直接測定した証明ではありません。

## イベントと隠蔽

map-object/normalとmystery/mana-surgeの正の確定離散増加を1件ずつ確認します。0、負、上限による無変化、自然回復、同じID、desire-recovery/renki/renki-tenfoldではEも音も発生しないこと。異なるIDを近接して発火し、各IDに1回以下のstart、各受け手の現在位置、異なる時計への誤紐付けがないことを確認します。

死者、退場、ベント、透明、画面外、失効、ルーム/セッション不一致、タブ非表示を「発火前」「GPU proof中」「既に再生中」で試します。ホスト可視性変化は同じ更新でinvalidateを呼ぶ契約です。抑制されたIDが復帰時に追い再生されてはなりません。ルーム/セッション切替で旧voice/activeを破棄します。

## SFX / 同期

実GPUで可視の初回が成功した後だけ、同じevent idの音が一度鳴ることを確認します。ミュート、非表示、verify、AudioContext未稼働で鳴らないこと。解除後に過去の音を鳴らさないこと。ACC2途中切替で音が頭から再開しないこと、音の進行と受領/満量の位相が離れないことを実聴します。

同じ原音のrate=2は時間と音高をともに上げます。音高を保持するtime-stretchは実装していません。常時ループ、残響の長い尾、未確認の命中音はありません。複数voiceの重なりは実デバイスで音量・歪み・可聴分離を判定します。数値ピーク検査は聴感評価ではありません。

## 記録欄

GPU検査ページの結果JSONに `quality.dark / quality.light` を手動入力できます。選択肢「読めた」は当該観察者・当該環境での観測を意味し、普遍的な品質保証ではありません。曖昧なら判断保留または棄却とし、技術passから自動補完しません。

作成環境で未実施のものは、shader、actual GPU pixels、動き、聴感、実音画同期、無説明読解、実ゲーム接続をすべてnot_runとしています。初期の配布レポートを書き換えず、実行先の結果を別ファイルとして保存してください。
