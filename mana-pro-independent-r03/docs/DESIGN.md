# r0.3の設計と適用範囲

## 課題と独立設計

ユーザーのr0.2報告は、Windows Chromeでshaderコンパイルと161位相GPU画素検査がpassした一方、H64暗明の全寿命では3段階の因果が読めなかった、という観測です。その見えを新作の形状見本にせず、特定のコード値が原因だったとも扱いません。本作の形状・内面・時間分布・音合成は新規です。イベント/所有者時計/一回限りSFXという非視覚の振る舞いだけを契約として保持します。

新設計は「点を順番に置く」方法ではなく、**三つの区画が最初から同じ連続面として存在し、その内側の状態が移る**方法です。身体を描かず、現在playerIdの足元と腹部設計オフセットへ場を置きます。新しい杯・機械・台座などの実体を追加する設定ではありません。ただし視覚だけでは器/支柱に誤認される可能性があり、これは未解決の知覚上のリスクとしてBのPerceptualReadabilityに記録しています。

## 区画・層・PH

| 状態と層 | 新しい形と位置（world units） | 時間応答 | 主に残す手掛かり |
|---|---|---|---|
| PH1 / L1 供給 | 足元y約−19..+10、全幅106。青い有色の広い折面と局所芯 | 供給量の減少に応じ内側の明部が狭くなる。外形は終了まで保持 | 広い足元面、明部と外縁、中央の実際の接合 |
| PH2 / L2 輸送 | y−10..−63、断面幅26..36。源から受領部まで重なる連続面 | 暗い面の内側を遅れ付きの密度前端が上へ進む。全面を点滅させない | H64で13..18pxの断面、内側の進行、切れない両端 |
| PH3 / L3 容量境界 | y−109..−53、全幅94。腹部の大きな受領領域 | 空の容量境界を発火時から終了まで保持 | 空き領域と接入口を同時に識別するための大きな面 |
| PH3 / L4 受領内容 | L3と同じPHの内側。人物・新しい器ではない | 到着後、下から上へ受領面積が増す。満量後に内部放射が中心へ寄る | 空き/充填の面積差、新しい到着境界と古い蓄積層 |
| PH4 / L5 既存背景受光 | 既存の暗/明試験面。本体の外側の局所範囲 | 同じframeの源・輸送・受領へ即時追従。機械的遅れなし | 元の背景を残した局所的な色・明度差 |
| OBS1/2 / L6 観測 | screen上の入力依存マスク、物体厚みなし | PH入力へ従属。独立した点滅なし | ごく局所的な拡散と表示色変換。本体がなくても形を作る処理にはしない |

層数は品質の尺度ではなく、PHと一対一でもありません。粒子、火花、光条、人物原画、床の仮接触影、レンズゴースト、文字を追加していません。素材名やノイズだけで形態を埋めていません。

## 量と時間

実行時の総尺は `src/contract.mjs` の `DURATION=1.6` 所有者実効秒だけです。`phase=age/DURATION`。形状定数と相対位相は `src/shape-data.mjs` のみからWGSL定数へ生成します。

供給済み量 E は `smoothstep(0.055,0.625,phase)`、受領量 R は同じ関数の入力を `phase−0.18` としたものです。source=`1−E`、transit=`E−R`、received=`R`。合計1を保つ**表示用の無次元量**であり、ゲームに付与するマナではありません。実獲得量の大小によって新しい魔法や部品数を増やしません。

搬送内の局所時間は、下から上への正規化座標に比例した遅れを引いたものです。phase約0.235から受領量が増え、約0.805で満量となります。0.83..0.96は満量を保持したまま内部の放射分布だけが中心へ集まります。受領面積や搬送接続を終端前に小さい一点へ縮退させません。

**終了方式を明示します。** 最後まで三つの支持形を保ち、phase=1で源・輸送・受領・周辺光・OBSを同じframeで除去します。終端前の包絡は約0.84までで、長いゼロ近傍フェードは採用していません。滑らかな全体フェードに見えることは保証しません。内部収束と一斉消失が自然に読めるか、急な切断に見えるかは実観察の判定事項です。この選択をもって棄却条件を緩めません。

移動中・ACC2 active・実効trueの3条件が揃った区間だけrate=2。それ以外はrate=1。切替点まで旧速度でageを積分してからrateを変更します。視覚とSFXはこの開始契約・速度契約を共有し、切替で再起動しません。

## 発光・色・不透明度・背景光・OBS

source/receivedは量、localFlux/bandは内側の密度状態、rgbは色と相対放射、coverage/alphaは画素被覆です。これらを同じ「明るさ」変数で代用しません。濃い外面と色のある内面、局所芯、新しい受領境界、保持された層で差をつけます。色はコバルトの源、シアンの搬送、紫の受領済み層へ役割を持たせています。色から温度、化学組成、実物理のエネルギー値を推定しません。

PH4の背景受光は `bg * (1 + min(irradiance,0.45))` という定性的な拡散面近似です。源のSDFとその状態から位置・減衰を与えます。暗い反射率では受光量も小さくなります。実際の3D法線、他物体遮蔽、実景マテリアルを解いた照明ではありません。

OBS1は既存の放射領域に束縛された短距離散乱近似です。実レンズのpoint-spread functionを測定したものではなく、本体の輪郭を保つための再合成前の局所項です。3つの入力それぞれを同じ時間/位置へ束縛し、全イベント合成でもlinear RGB各0.075を上限にします。世界内の背景受光とは別変数です。

処理順は「背景の局所受光 + OBS1 → PH2/PH1/PH3の有色本体をcoverageでover → OBS2のtone/sRGB → RGBA8中間画面 → textureLoadで同解像度present」です。すべてをaddにせず、straight colorとcoverageを明示して二重乗算を避けます。OBS1は本体により覆われるため、保護する内面や輪郭を白いglowで置き換えません。中間画面textureはGPU内の出力先で、画像ファイル素材ではありません。

白飛びの全面禁止は設けていません。局所の数値が表示範囲を超えることと、主形が白い塊になることを区別し、後者は無説明読解の失敗として評価します。

## サンプリング・同時発生・低減モーション

1wu=0.01mはB worldとの換算用の設計仮定であり、ゲームの実測単位を断定しません。runtimeはgame unitsのy下向きを扱い、B設計ではy上向きへ変換します。H64=0.5px/wuで固定bufferを用います。OSのDPIやブラウザーの表示再標本化は別途記録してください。

密度帯は連続断面の内部属性です。低減モーションでは帯変動だけを固定し、供給・到着・面積蓄積・終端は残します。低減モーションが医療上の安全性を保証するという主張はしません。

近接した異なるevent idは別の時計・状態・GPU token・voiceを持ちます。同一受け手の未確認初回フレームは逐次化し、同形状が完全に隠れたイベントを一括して発音済みにしません。既に走っているものは重なり合います。完全重複時に各イベントを人が視覚だけで数えられることや、64件同時の品質は未検証です。リソース上限ではfail-closedとし、遅れて再発火しません。

## B適用と検証の限界

完全なB設計は `design/mana-r03.B-Expression-2.json`。全PHのPhysicalModel/ScaleRegime/8領域/知覚/動態/因果評価/VisualProjectionを保持します。非該当の熱・流体・波動・濡れ等は理由付きlatentで保持し、領域数を満たすための物体は作りません。MagicArchitecture、人物/姿勢、登録キーワードの一括起動はありません。

実装箇所の索引は `docs/RULE_MAP.md` / `design/rule-implementation-map.json`。ローカル検査は構造と参照を確認します。B正本の公式検証器を実行したものではありません。背景の光輸送近似と実身体の腹部位置の一致には限界が残り、SemanticReconciliationはWarningです。GPU・聴感・品質評価はnot_runです。
