# RPG E r1 gallery package candidate

This package contains the frozen `sol-rpg-heavy-zero-r1` module and its local WebGPU preview closure. The E kernel, approved pose metadata/images, hypothetical physical fixture geometry, and source provenance are unchanged. A package-local `?embed=1` controller now runs the same preview module as a continuous fixture demonstration: each 1200 ms local E-clock event is followed by a 300 ms pause, then a fresh local cause/source/attempt/sound identity. This is an invented demonstration fixture, not a real producer event, authoritative game clock, or game integration.

The embedded page hides the standalone header and controls, fits its canvas to the iframe, and leaves the child `#error[role=alert]` visible for parent diagnostics. Standalone controls and one-shot behavior remain on the default route. Embed playback is silent until the gallery invokes `window.__gallerySfx.activateFromGesture(item)` during a user gesture. That unlock call creates/resumes Web Audio in the gesture and only submits authored finite PCM through the module's exact submitted-receipt gate. `?verify=1` stays hard-zero: no AudioContext is created, the bridge reports silent, and no unlock occurs. Optional `reviewAgeMs=0..1199` holds an actual local fixture age for silent phase inspection; omit it for the 1× 0–1200 ms loop.

The host's local monotonic performance clock drives only its explicitly hypothetical fixture E clock. It is not converted to a server/game clock. The host still requires WebGPU and the supplied, same-device physical surface textures (base radiance, albedo, signed normal, world position plus mask); if these are missing or invalid, it shows an error instead of inventing lighting success.

**Native WebGPU replay remains pending.** The prior black capture predates both the CSS feedback repair and correction of an HTTP 415 stylesheet response. There is no post-repair actual pixel/WGSL-driver confirmation yet. The 41 creative contract checks and host/unit tests do not establish native rendering, visual quality, audio listening, adoption, or game integration. Do not list the package as technically replayable until primary native review sees actual pixels and no runtime/GPU errors.
