# RPG E r1 runtime preview host

This is a standalone technical preview for `sol-rpg-heavy-zero-r1`. It replays the frozen shader module in a real browser WebGPU device when the browser supports it. The receipt, room, impacts, and 3D light positions are explicitly hypothetical. Approved male-left r5/r6 pose hashes and pivots bind the firing mouth; the scene body is a simple 112-logical-unit preview mesh, not the source sprite and not a claim about game rendering.

Serve this directory and its parent `rpg-e.mjs` over HTTP, then open `runtime-preview/index.html`. The host uses no library or network dependency. `?verify` selects hard-zero audio mode; it hides the sound-enabled start control, creates no audio context, and cannot be unmuted by this page. Normal mode starts muted. **Play with sound** calls `AudioContext.resume()` from that click and admits only finite launch/impact PCM after the exact E submission receipt exists. Sounds retain source IDs and use the same E age as the submitted visual frame. A gated sound ID is consumed and never replayed after visibility or lock changes.

Normal playback advances the fixture's E clock and actor clock together at 1× over 0–1200 ms. The slider permits paused inspection. The chosen sample is normal or enhance; reduced motion retains the module's built-in coverage. For tool-assisted phase inspection, `?verify=1&reviewAgeMs=180` holds the **actual fixture E age** at exactly 180 ms and records that frame through the same module and GPU submission path. It accepts integer ages 0–1199, stays silent, and hides playback controls; omit `reviewAgeMs` for the full 1× run. This host does not change the submitted E shader, audio synthesis, event design, or production game.

Each frame builds one command encoder. For a planned frame the order is the module's physical-surface lighting pass into an `rgba16float` HDR target, the E VFX pass, and a small final tone-map pass into the WebGPU canvas. The host submits that encoder only through the exact receipt returned by the module. All four surface textures and the target are created on the same device. Their explicit geometry data includes base radiance, linear albedo, signed normals, world positions, and a validity mask; background texels have mask zero. If those inputs are unavailable, stale, aliased, or rejected, the host shows the error and stops instead of claiming lighting succeeded.

Validation is intentionally scoped: `host-ownership.test.mjs` exercises URL audio mode, generated mask data, and stale/aliased/foreign resource lease rejection. `node --check preview-host.mjs` checks syntax. The parent `contract.test.mjs` checks the module's pure and mocked API contract. These do not prove actual driver WGSL compilation, pixel output, visual quality, listening quality, game integration, or adoption. Actual GPU review belongs to the parent task.
